# Design decision register

> UX3 supersedes D-002, D-004, D-007, D-010, and parts of D-011 below. See [UX3 iteration log](UX3_ITERATION_LOG.md) and [Design System V3](DESIGN_SYSTEM_V3.md) for current decisions.

**Decision status:** candidate decisions for owner review, not final visual approval. Source-level decisions can be reviewed here; visual outcomes remain unverified.

| ID | Decision | Evidence and alternative | Tradeoff / status |
|---|---|---|---|
| D-001 | Use a compact Explorer-like shell with header, Files/Trash rail, breadcrumb, search, commands, and table. | Phase 0.5 information architecture and Windows design basics; dashboard/card layout was considered. | Familiar and file-focused. Implemented; owner visual review pending. |
| D-002 | Keep the default build honest: no open vault and no real operation; empty-state copy explains unavailable vault support without disabled Create/Open buttons. | ADR-012 and baseline Critic P1 about first-launch hierarchy; making controls functional would cross the Phase 1A boundary. | Source implemented; GUI verification pending. UX3 supersedes disabled buttons. |
| D-003 | Add an opt-in `design-preview` feature plus `--design-preview` flag with deterministic in-memory data. | Owner brief requires a full view of product states but prohibits real vault access. Always-on synthetic data was rejected. | Additional feature mode; default shell remains empty. Implemented. |
| D-004 | Use the exact original Java product husky PNG in the Rust UI and window icon, with provenance recorded. | The source/destination SHA-256 matches; user authorized reuse within this product repository. Public redistribution rights are not established. | UX3 supersedes the placeholder. Owner/legal approval is required before public asset redistribution. |
| D-005 | Use a leading navigation marker, selected surface, label, and AccessKit selected state. | Baseline Critic P1 found a color-only selected cue risk. | Adds a small visual marker; actual contrast and rendering are unverified. |
| D-006 | Use a virtualized table with Name, Type, Size, plus `Modified · sample` only in the synthetic preview. | ADR-012 excludes Modified from production semantics; preview fixtures need deterministic timestamps for design testing. | Synthetic label avoids an implied VF1 promise. Implemented; production remains Name/Type/Size. |
| D-007 | Keep row focus separate from selected IDs; selection uses stable IDs across sort/search. A changed effective query clears selection; sorting and unchanged queries preserve it. | Approved selection rules adapted to avoid hidden destructive targets. | UX3 supersedes selection persistence through changed filtering. Model tests pass; pointer/keyboard integration remains unverified. |
| D-008 | Use primary New Folder and Import actions; selection-dependent actions sit in the selected-items strip and context menu. | Owner direction, Windows command surfaces, and Raycast contextual-action reference. A flat toolbar was rejected. | Better action hierarchy; contextual consistency is source-reviewed only. |
| D-009 | Confirm Move to Trash and permanent deletion in this preview; show plaintext warning before simulated export. | Phase 0.5 destructive-action guidance and security boundary. One-step Trash with undo was considered but needs a real undo contract. | Avoids inventing backend undo. Implemented as in-memory state only. |
| D-010 | Default to System appearance, offer Light and Dark session overrides, and use Dark if the host appearance cannot be resolved. | Current UX3 direction; `AppearancePreference` separates preference from resolved appearance. | UX3 supersedes the prior Light/Dark-only choice. OS transitions and rendered contrast remain unverified. |
| D-011 | Use standard egui widgets where practical; custom-painted icon buttons/navigation and rows receive explicit human-readable widget metadata. | eframe 0.37 AccessKit support; custom painting still needs explicit semantics. | Source metadata is not proof of Windows UIA/Narrator quality. Manual validation required. |
| D-012 | Cache the visible sorted projection by query, location, sort, and model revision; render rows with `TableBuilder::rows`. | 10,000-entry fixture and release benchmark show sorting can be cached while TableBuilder virtualizes rows. | Additional GUI-independent preview state only; benchmark measures model projection, not rendered frame time. |
| D-013 | Keep preview passwords transient/masked; no authentication, file picker, file read/write, network, or crypto. | Owner security boundary and reviewed baseline. | Screens demonstrate composition only; do not treat sample actions as product functionality. |
| D-014 | Keep security and offline context in compact text, not repeated lock badges or cloud status. | 1Password and Proton references considered only for state clarity; their recovery/sync models do not fit. | Simpler security language; owner product copy review remains open. |
